# 《散步企鵝》全服聊天

## 功能規格

- 玩家從主畫面的「雪地聊天」按鈕開啟頻道 1。預設收合，按下才會建立聊天室連線，收起會卸載聊天室。前端目前只啟用一個頻道。
- 輸入暱稱即可發言。遊戲存檔、金幣和簽到資料不會傳給聊天室。
- 遊戲開啟時產生並在本機保留 UUID v4。四房使用同一組 UUID，聊天室只公開末五碼。直接開 Apps Script 網址時會用該頁自己的訪客識別碼。後綴可協助辨識，但可能重複，且不是登入憑證。
- 暱稱上限 20 字元，訊息上限 200 字元。聊天室顯示最近 50 則，時間以台灣時間顯示。瀏覽時只把訊息當文字顯示。
- 開啟時立即讀取，之後約每 15～20 秒更新。關閉聊天室停止輪詢，切到背景暫停，回到前景時保留重試時間。讀取失敗會保留已載入訊息並拉長重試間隔，最高約 60～65 秒。已送到 Google 的請求可能仍會完成，快取命中也會用到一次 Apps Script 執行。
- 讀取先走 Apps Script 的共用快取，快取最多保留 10 分鐘。快取缺失時，只有取得短鎖的請求會補讀。試算表失敗後，暫停存取試算表 30 秒，已有快取仍可讀。
- 公開發言由 Apps Script 寫入私人試算表。每位訪客間隔至少 8 秒，全房間至少間隔 1 秒。訪客限制以瀏覽器識別碼計算，清除資料或更換識別碼可重置，所以另有全房間上限。
- 寫入失敗或沒有收到確認時，聊天室保留目前輸入。原字重送會沿用訊息 ID，後端在最近 50 則內去重。試算表保存完整紀錄，刪除或修改舊列後，顯示可能要等共用快取更新。

## Google 端部署

目前只需使用頻道 1 的 Google 帳號與私人試算表。已有部署時，更新 `Code.gs` 和 `Chat.html`，再用「管理部署」將原部署更新至新版本。現有的 `/exec` 網址可沿用。

1. 建立一份專用的 Google 試算表，保持私人。把底部分頁改名為 `Chat`，A 欄留空。從網址 `/spreadsheets/d/…/edit` 中複製試算表 ID。
2. 在 Apps Script 建立獨立專案，把本目錄的 `Code.gs` 貼到程式碼檔。新增一個名稱為 `Chat` 的 HTML 檔，把 `Chat.html` 的完整內容貼進去。
3. 在 Apps Script 的「專案設定 → 指令碼屬性」新增 `CHAT_SHEET_ID`，值為試算表 ID。
4. 選「部署 → 新增部署 → 網頁應用程式」。執行身分選「我」，存取權選可包含未登入訪客的「任何人」。使用有該試算表編輯權的 Google 帳號授權。若帳號政策沒有提供匿名部署，玩家免登入的流程便無法使用。
5. 複製部署網址，以 `/exec` 結尾。先用無痕視窗打開它，確認無需登入，並用兩個視窗測試收發。

## 接上遊戲

若網頁顯示暫時讀不到訊息，但「執行作業」沒看到錯誤，可在程式編輯器選擇 `diagnoseChatSetup_` 並執行。它會略過快取，直接讀取試算表。成功時執行記錄會顯示 `Chat spreadsheet OK`；失敗時會顯示實際的例外。執行這個診斷無須重新部署。

頻道 1 的網址使用 `VITE_CHAT_ROOM_1`。本機可放在專案根目錄的 `.env.local` 後重新建置。GitHub Pages 工作流程會讀取同名的 GitHub Actions 倉庫變數。公開版沒設定網址時會隱藏聊天入口。試算表 ID 和管理權限留在 Google 端。

遊戲將聊天室網頁嵌入自己的視窗，聊天室用 `google.script.run` 呼叫 Apps Script。最後還要用公開遊戲頁和兩個未登入的瀏覽器環境，確認 Google 頁面能成功嵌入並互相收到訊息。

## 本機測試

執行 `node scripts/chat-local.mjs --test` 可測試四房隔離、讀寫、故障退避與重試。測試直接載入 `Code.gs`，每房各有一份記憶體模擬試算表。執行 `node scripts/chat-local.mjs` 後，本機遊戲會自動連到 `127.0.0.1:4182`。測試訊息在重啟模擬器時會清除。
